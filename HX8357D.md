# Adafruit HX8357D SPI display

The HX8357D is selectable as video backend **5** on both Pico targets. The bare
RP2040 Pico and Adafruit 320x480 module are physically tested on COM14. The
RP2350 version is generated and compiled; that panel has not been connected to
the Pico 2 W carrier for a physical emulator test.

The default is **30 FPS complete-frame presentation** with NTSC guest timing,
about 60.1 emulated frames/s. Pico remains at 200 MHz; Pico 2 remains at its
normal 150 MHz. CPU, PPU pixel rendering, APU and audio implementations are
unchanged. The existing display-presentation selection guards include backend 5.

## Select the emulator display

```powershell
tools/build.ps1 -Compiler path\to\PureMetalForge.exe -Target rp2040 -Display hx8357d
tools/build.ps1 -Compiler path\to\PureMetalForge.exe -Target rp2350 -Display hx8357d
```

Outputs are `firmware/nes-pico-w-hx8357d.uf2` and
`firmware/nes-pico2-w-hx8357d.uf2`. The RP2040 image runs on a bare Pico as well.
The wrappers select `#NES_AUDIO_BACKEND=0` and `InputPhysicalEnabled=0` for the
standalone hardware: the APU still runs, physical sound output is silent, and
USB controls remain available. Copy the wrapper to independently select
Bluetooth on a W board, a custom audio plugin, or physical input. See
[OUTPUTS.md](OUTPUTS.md). The display driver does not choose audio or controls.

Load owned ROMs with the ordinary ROM-loader tool/UI. The driver presents the
unchanged 256x240 RGB565 image at **(112,40)** in **480x320 landscape**. The host
FPS/EMU counters are at the screen's upper left, outside the emulated image.

`Hx8357SpiKhz=40000` requests the pixel clock; integer dividers produce
**33.333 MHz on Pico** and **37.5 MHz on Pico 2**. Setup and addressing commands
use `Hx8357CommandKhz=1000` (1 MHz). Dividers are resolved once with CS high;
switching from RAMWR to the pixel clock sends no extra probe byte. These clocks
are configuration choices, not claims about every module's maximum rate.

The plugin owns SPI1, DMA channel 0 and GP10/11/12/13/16/17. Other output plugins
must use different resources. DMA sends the existing two 120-row buffers and
waits for the SPI shifter to finish before releasing CS. No full-frame buffer
is added. `Hx8357FrameDivider=2` presents alternate completed frames; a 512-byte
scratch row receives skipped RGB stores, preserving buffers while DMA owns them.
All emulated PPU work still executes. These globals can be set in a custom
wrapper before `Main()` without changing the emulator implementations.

## SPI1 wiring

Connect with USB unplugged. For the Adafruit 3.5-inch breakout:

| Display signal | Pico signal | Physical pin |
|---|---|---|
| VIN / 3-5V | USB VBUS, 5V | 40 |
| GND | GND | 18 |
| CLK | GP10 | 14 |
| MOSI | GP11 | 15 |
| MISO | GP12 | 16 |
| CS | GP13 | 17 |
| D/C | GP16 | 21 |
| RST | GP17 | 22 |

Enable SPI by closing the IM2 jumper, or connect IM2 to the display's 3Vo output.
Leave Lite unconnected for the default enabled backlight. Touch and SD wiring
are unused. This power/jumper arrangement is specific to the Adafruit breakout;
see [its pinouts](https://learn.adafruit.com/adafruit-3-5-color-320x480-tft-touchscreen-breakout/pinouts)
and [SPI instructions](https://learn.adafruit.com/adafruit-3-5-color-320x480-tft-touchscreen-breakout/spi-wiring-and-test).

## Standalone diagnostic: build and run

```powershell
tools/build.ps1 -Compiler path\to\PureMetalForge.exe -Source rp2040/Diagnostics/hx8357d.picow -Output rp2040/Diagnostics/hx8357d.uf2 -Port COM14 -Seconds 10
```

Use an explicit output path as shown to keep the normal emulator images.
Opening USB serial at 115200 baud starts the diagnostic once. `r` resets and
repeats it; `i` reads the registers again. After drawing, the firmware services
USB and the watchdog without animation, emulation or wireless initialization.
The diagnostic image ends at 0x10004900, below the ROM store at 0x10050000.

Initialization uses Adafruit's HX8357D register sequence at 1 MHz, register reads
use about 100 kHz, and drawing requests 8 MHz. With the Pico at 200 MHz the actual
drawing bus is **7.692307 MHz**. DMA channel 0 writes RGB565 rectangles without
a full-screen framebuffer allocation. The static landscape pattern contains
eight vertical white/yellow/cyan/green/magenta/red/blue/black bars, a white outer
border, corner numbers 1/2 above 3/4, and a 256x240 outline at (112,40).

## Standalone diagnostic results

The final run passed **51 checks with zero failures**. These include four
physical register-readback checks, SPI/DMA completion and restored bus state.
Power mode read 9C; pixel-format read 05. A deliberate rotation-register change
read back 60 and then A0, proving actual bidirectional communication rather
than accepting a disconnected FF-only bus. The operator confirmed the expected
physical pattern, colors and orientation. Drawing took 379,042 microseconds;
this is a diagnostic drawing measurement, not an emulator FPS benchmark.

Raw serial ID replies are preserved without claiming a literal 0x8357 model
code in the returned bytes. Register readback and the visual test validate this
HX8357D configuration; initial reads before setup returned FF because the
initialization had not yet enabled the display's SDO output.

[Raw output and image/source hashes](rp2040/Diagnostics/hx8357d-results) are
included. The RP2350 version is generated and compiled only; it has not been
flashed onto the Pico 2 W carrier or physically tested.

The original Adafruit BSD notice for the initialization sequence is retained in
[licenses/Adafruit-HX8357.txt](licenses/Adafruit-HX8357.txt).

## Emulator output validation

The bundled plugin passed **99 checks, zero failures** on COM14, including live
power/rotation/pixel-format readbacks, skipped-frame isolation, DMA busy rejection,
completion, CS release and abort. Ten unpaced complete-frame transfers took
323,867 microseconds at 33.333 MHz. The operator confirmed the centered game
picture, colors and host FPS counter. Four 40-second board runs produced:

| Game | Mapper | Emulated FPS | Displayed FPS | APU samples/s | Errors |
|---|---|---|---|---|---|
| Super Mario Bros - Duck Hunt (U).nes | 66 | 60.098 | 29.974 | 47999.70 | 0 |
| Contra (U).nes | 2 | 60.097 | 29.999 | 47999.82 | 0 |
| Castlevania (U) (PRG 0).nes | 2 | 60.097 | 29.998 | 47999.48 | 0 |
| Gradius (U).nes | 3 | 60.096 | 29.998 | 47999.00 | 0 |

Mario, Contra and Castlevania captures reached gameplay. The standard bare-board
profile is silent; sample counts do not claim a physical speaker test. CPU, PPU
pixel-rendering and audio implementations were preserved. The existing PPU
presentation guards were extended to select backend 5. Both the existing
ILI9341 image and the full regression image rebuilt byte-identically; the latter
was not rerun solely for this display addition.

Emulation was stopped afterward at the four-game menu, measured at 30.0 displayed
FPS. [Raw telemetry, firmware hashes and preservation checks](rp2040/Diagnostics/hx8357d-emulator-results)
are included. Pico 2 physical validation remains pending.
