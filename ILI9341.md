# ILI9341 SPI display

Select video backend **4** for a standalone 240x320 ILI9341 module. The driver
uses SPI1 and presents a centered 256x240 NES image on a 320x240 landscape
display. CPU, PPU pixel rendering, and APU algorithms are shared with the
existing builds. Video, audio, and physical controls remain independent.

## Wiring

Wire with USB disconnected. These are **GPIO numbers** and the corresponding
40-pin Pico header positions; the pinout is the same on Pico/Pico W/Pico 2/Pico 2 W.

| Display pin | Pico signal | Physical pin |
|---|---|---|
| VCC | 3V3 OUT | 36 |
| GND | GND | 18 |
| SCK | GP10, SPI1 SCK | 14 |
| SDI / MOSI | GP11, SPI1 TX | 15 |
| SDO / MISO | GP12, SPI1 RX | 16 |
| CS | GP13 | 17 |
| DC | GP16 | 21 |
| RESET | GP17 | 22 |
| LED | 3V3 OUT | 36 |

The separate SD-card header is unused. This wiring belongs to the standalone
module; check carrier-board pin ownership before connecting it alongside other
hardware. The tested red 2.2-inch board matches the LCDWiki MSP2202 module.
Its [vendor pin table](https://www.lcdwiki.com/2.2inch_SPI_Module_ILI9341_SKU:MSP2202)
specifies 3.3 V on LED for continuous backlight. Other modules may require a
resistor or a backlight transistor: follow their own circuit information.

## Select and build

```powershell
tools/build.ps1 -Compiler path\to\PureMetalForge.exe -Target rp2040 -Display ili9341
tools/build.ps1 -Compiler path\to\PureMetalForge.exe -Target rp2350 -Display ili9341
```

Outputs are `firmware/nes-pico-w-ili9341.uf2` and
`firmware/nes-pico2-w-ili9341.uf2`. The RP2040 image also runs on a bare Pico.
The standard wrappers select silent audio (`#NES_AUDIO_BACKEND=0`) and USB-only
controls (`InputPhysicalEnabled=0`) for the standalone test hardware. They do
not attempt to initialize a wireless chip on a bare board.

For a custom profile, copy the wrapper, retain video backend 4, and independently
select Bluetooth (on a W board) or your own audio plugin. Set
`InputPhysicalEnabled=1` before `Main()` for the existing LAFVIN button/joystick
wiring, or implement your own input. See [OUTPUTS.md](OUTPUTS.md).

Load owned ROMs with the ordinary ROM loader and `--port COM14` (replace the
port with your board's actual port). USB gameplay keys are `s` Start, `a` A,
`b` B, `u` up, `n` down, `l` left and `r` right (brief presses). Uppercase
`R` holds right for about five seconds; `0` releases the current input.
The standard loader UI works without changing the emulator build.

## Refresh and DMA

The default is **30 FPS display output**, while guest timing remains NTSC,
about 60.1 emulated frames/s. Alternate completed frames are presented. A
512-byte disposable row receives the skipped frame's RGB stores so the DMA
buffers remain intact. The PPU still executes its normal emulated work.

The driver sends complete frames through DMA channel 0, switching between the
existing two 120-row buffers. It does not allocate another full framebuffer.
It waits for both DMA completion and SPI shifter idle before releasing CS.
The FPS/EMU HUD occupies the left 32-pixel margin, outside the emulated image.

`Ili9341SpiKhz=40000` is a conservative requested write clock, not a controller
maximum. Integer divisors produce **33.33 MHz on the 200 MHz RP2040** and
**37.5 MHz on the 150 MHz RP2350**. A 256x240 RGB565 image requires 58.98 Mbit/s
at 60 FPS before commands and pauses; these default clocks cannot transmit it
60 times/s. Higher clocks require validation on the actual module and wiring.
`Ili9341FrameDivider=1` requests every frame, but cannot remove that bandwidth
limit. Set these globals in a custom wrapper before `Main()`.

The ST7789 Display Pack's 50 MHz RP2040 setting is likewise a firmware
configuration, not a claim that ST7789 cannot exceed 50 MHz. Its notes explain
the divider choice and why the physically tested 100 MHz LAFVIN path has more
bandwidth: [DISPLAY-PACK2.md](DISPLAY-PACK2.md).

## Validation scope

On 2026-10-16 the attached module returned controller ID **0x9341**. On the bare
RP2040 Pico at COM14, the operator saw the diagnostic's colored boxes; 97
controller-ID, input isolation, DMA, frame cadence and ownership checks passed.
Ten unpaced full-frame transfers took about 322,875 microseconds at 33.33 MHz.
The full emulator suite also passed 1,926,732 checks with zero failures.

Exploratory RAMRD pixel reads returned only FF on this module. They are logged
separately and **are not counted as passed pixel-readback validation**. USB
framebuffer captures check the emulated image, not the panel's physical pixels.
The operator also confirmed the emulator picture, colors and orientation.
The RP2350 ILI9341 build is compiled; this display has not been connected to the
Pico 2 W for a physical test.

Forty-second board runs, using the default silent-output profile:

| Game | Mapper | Emulated FPS | Displayed FPS | APU samples/s | Errors |
|---|---|---|---|---|---|
| Super Mario Bros - Duck Hunt (U).nes | 66 | 60.097 | 29.999 | 47999.80 | 0 |
| Contra (U).nes | 2 | 60.098 | 29.974 | 47999.73 | 0 |
| Castlevania (U) (PRG 0).nes | 2 | 60.097 | 29.998 | 47999.48 | 0 |
| Gradius (U).nes | 3 | 60.097 | 29.998 | 47998.75 | 0 |

Raw telemetry and firmware hashes are in
[rp2040/Diagnostics/ili9341-results](rp2040/Diagnostics/ili9341-results).
These runs include startup, rather than selecting the fastest interval. Extra
Start-button checks reached gameplay in Mario and Contra. The final menu ran at
30.0 FPS with guest emulation stopped. Silent
output does not validate a physical DAC or Bluetooth speaker.

The new silent build exposed an existing ROM-loader allocation error:
`RomCrcTable(255)` allocated 255 elements although the CRC uses indices 0..255.
It now allocates 256. This avoids an overlap with the following global and
allows uploads to verify independently of build layout.

The initialization register values are adapted from Adafruit's ILI9341 driver;
the original BSD notice is in [licenses/Adafruit-ILI9341.txt](licenses/Adafruit-ILI9341.txt).
